# design-sync notes — Harmost UI

Project: `Harmost UI` — https://claude.ai/design/p/a80f90ec-0df2-47b8-ac6e-118143b219d3
Source: `apps/front` (shape: `package`, via an explicit entry barrel).

## Why this repo needs an unusual setup

`apps/front` is an **application, not a component library**. It has no `dist/` entry, and
`apps/front/package.json` is a 3-line private stub with no `main`/`module`/`exports`. Three
files bridge that gap. All three are committed and all three are inputs to the sync:

- **`apps/front/.ds-entry.tsx`** — the entry barrel passed as `--entry`. Re-exports the 14
  components plus the recharts primitives. Also what pins `PKG_DIR` to `apps/front` (the
  converter walks up from `--entry` to the nearest named `package.json`). **Add new components
  here and to `componentSrcMap` together** — `componentSrcMap` is what creates the card, the
  barrel is what puts the symbol in the bundle.
- **`apps/front/.ds-preview-shell.tsx`** — the `cfg.provider` wrapper (dark surface + router).
- **`apps/front/tsconfig.ds-types.json`** — emits `.d.ts` into `apps/front/types/`, which is
  where `findTypesRoot()` picks them up. Not part of `nx build front`.

Both `apps/front/types/` and `apps/front/.ds-styles.css` are generated by `cfg.buildCmd` and
gitignored — a fresh clone must run `buildCmd` before the converter.

## Gotchas, in the order they bite

- **Tailwind is a build step, so `cssEntry` must point at COMPILED css.** `src/styles.css` is a
  Tailwind v4 source file (`@import "tailwindcss"`, `@theme inline`, `@apply`) — it holds the
  tokens but not one utility class. `cfg.buildCmd` runs `nx build front` and copies the hashed
  `dist/apps/front/assets/index-*.css` to `apps/front/.ds-styles.css`, which is what
  `cssEntry` reads. Pointing `cssEntry` at `src/styles.css` ships tokens with no utilities and
  every preview renders unstyled.
- **The app is dark-only** (`<html class="dark">` in `index.html`). Without the provider every
  card renders dark-on-white and reads as broken.
- **`dark` goes on `document.documentElement`, not a wrapper div.** Radix portals
  (`TooltipContent`) mount on `document.body`, outside any wrapper, and were resolving `:root`
  (light) tokens — the tooltip pill came out near-black on a near-black page.
- **`AgentCard` needs a router.** It renders a TanStack Router `<Link>` and throws
  `Cannot read properties of null (reading 'stores')` without one. The preview shell runs a
  memory router and passes the card's tree through `SlotContext`, because `RouterProvider`
  renders the matched route rather than its children.
- **A second copy of recharts renders nothing.** `ChartContainer`'s `ResponsiveContainer`
  silently draws an empty chart when its child comes from a separately-imported recharts. Fixed
  by re-exporting the recharts primitives from `.ds-entry.tsx`; previews import them from
  `'front'`. This is also why the conventions header tells the design agent to do the same.
- **Only `MetricAreaChart` and `MetricsCard` declare a named `<Name>Props` interface**, and that
  is the only shape the extractor resolves. Every other component types its props inline on the
  destructured parameter and came out as `[key: string]: unknown`, so its contract is written by
  hand in `cfg.dtsPropsFor`. Domain types (`Agent`, `JobState`, `LogLine`) are inlined there
  because a `dtsPropsFor` body has no prelude to import from. **`Card` keeps an index signature
  deliberately** — it really does accept all `<div>` props.
- **Relative vs absolute timestamps differ per component.** `MetricsCard` formats relatively, so
  its preview anchors to `Date.now()`. `AgentCard` prints `toLocaleString()` absolutely, so its
  preview uses fixed ISO literals — a `Date.now()` value there renders whatever the rendering
  machine's clock says (the capture browser's clock reads 2024, which produced
  "Last seen 5/15/2024" and "Updated in 2 years").
- **Preview layout glue uses inline styles, not Tailwind classes.** The shipped CSS is compiled
  against `apps/front`'s own content scan, so a utility used *only* in a `.design-sync/previews/`
  file has no rule. Classes that the app itself already uses are safe.
- **`.design-sync/config.json` rejects unknown top-level keys**, including `"//comment"` keys.
  Explanations go here, not in the config.
- **Playwright must match the cached chromium.** `~/.cache/ms-playwright` holds `chromium-1228`,
  which is pinned by **playwright 1.61.0** — installed into `.ds-sync/`, not the repo. A
  different version fails with `browserType.launch: Executable doesn't exist`.
  `DS_CHROMIUM_PATH` is the escape hatch.

## Known render warns

None. The final validate run was clean — 14/14 render, no warn lines.

## Deliberate cosmetic compromise

Card groups are derived from src paths, so they came out `agents`, `jobs`, `shared` and
`metrics-card`. The first three mirror the repo's feature architecture (ADR 0008) and read
fine; **`metrics-card` is a folder artifact** — `MetricsCard` and `MetricAreaChart` live in a
nested `metrics-card/` directory. Doc frontmatter `category:` cannot fix it: the converter only
applies a doc category when the derived group is `general`/`misc`, and `cfg.overrides` has no
group key. The only fix is forking `lib/source-kit.mjs`, which was judged not worth a permanent
re-sync merge burden for a section label. Revisit if the pane grouping bothers anyone.

## Re-sync risks — what to watch

- **`.ds-entry.tsx` and `componentSrcMap` drift.** A component added to `apps/front` appears in
  neither automatically. The sync will happily report success while silently missing it.
- **`cfg.dtsPropsFor` is hand-written and CANNOT rot loudly.** If someone changes a component's
  props, the emitted `.d.ts` keeps describing the old shape and nothing fails. Re-read the 11
  entries against source whenever components change. Converting a component to a named
  `<Name>Props` interface lets the extractor take over — delete its `dtsPropsFor` entry when
  that happens.
- **The conventions header names real classes and tokens.** They were all verified against
  `_ds_bundle.css` at sync time. Re-verify after any `styles.css` change; a class named there
  that no longer compiles sends the design agent to a rule that does not exist.
- **`buildCmd` globs `dist/apps/front/assets/index-*.css`.** If the Vite build ever emits more
  than one top-level CSS asset, that glob copies an arbitrary one.
- **Only three components were verified against a populated data series**
  (`MetricAreaChart`, and `MetricsCard`/`RadialGauge` by proxy). `MetricsCard`'s own card can
  only ever show a single sample, because `useMetricsHistory` buffers per mount and the hub
  stores no metrics history — its sparklines are sparse by construction, not by mistake.
- **Assumed toolchain:** node 22, npm workspaces, chromium 1228 already cached. Nothing is
  fetched from the network at build time.
